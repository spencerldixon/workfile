# `wf inbox` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `wf inbox` Bubble Tea screen listing all activity on the person's work, with what needs them marked, clearable locally, polling sparingly.

**Architecture:** Pure inbox logic, settings and local state in `internal/workfile`. A neutral `Activity` read through new `tracker`/`codeHost` methods in `internal/provider` (GitHub two-phase poll, Jira updated-since search). A no-shell command runner in new `internal/run`. Screen, polling and plain output in `internal/cli`.

**Tech Stack:** Go, `charm.land/bubbletea/v2`, `charm.land/bubbles/v2`, `charm.land/lipgloss/v2`, GitHub GraphQL, Jira REST.

**Spec:** `docs/superpowers/specs/2026-11-17-inbox-design.md`

**Prerequisite:** builds on the uncommitted `wf tracker` work on `lint-redesign` (`tracker_settings.go`, `next_actions.go`, tracker screen). Commit that first, then branch `inbox` from it.

## Global Constraints

- Workfile only reads. No write to Jira or GitHub, ever. Clearing is local.
- Bubble Tea, Bubbles, Lip Gloss **v2 only**. Never import v1 packages.
- Colours: only `lipgloss.ANSIColor` 1 red, 2 green, 3 yellow, 6 cyan, plus faint and bold. Through the `theme` helpers. No emoji.
- Symbols: `✗` red needs work, `‼` red bold out of policy, `●` cyan asked of you, `✓` green ready, `!` yellow cannot check, `○` faint information.
- All provider text through `clean` before printing. Never print provider response bodies.
- Plain output (piped, `NO_COLOR`, `TERM=dumb`): no escapes, URLs written out, no animation.
- Panels: title plus soft background, no borders, no edge bar, full width.
- Tests use made-up responses; anonymous names (Alice, Bob, Charlie, `example-*`, `example.com`).
- No em dashes in code, docs or copy.
- Verify with: `eval "$(mise env -s bash)"; go vet ./... && go test -race ./...`

## Review Focus

1. A provider fails or times out mid-poll (token expired, GitHub 502): screen stays up, last known rows stay, a `!` row names the connection, next poll retries. Test in Task 7.
2. `inbox.json` is corrupt, from an older shape, or its folder is unwritable: screen opens with fresh state; a write failure shows a toast once and never crashes. Test in Task 3 and Task 8.
3. Provider text carrying escape sequences or newlines (PR title, comment body, login): the row stays one line with no escapes. Test in Task 9.
4. `a` on a row whose prompt needs `{pr}` but the row has none, or whose agent binary does not exist: red toast, row stays, no note written. Test in Task 8.
5. More than 100 PRs in flight: change check batches `nodes(ids:)` by 100 and never asks for timelines of unchanged PRs. Test in Task 6.

### Task 4: Build inbox rows (pure)

**Files:**
- Create: `internal/workfile/inbox.go`, `internal/workfile/inbox_test.go`

**Interfaces:**
- Consumes: `Activity`, `InboxState`, `NextActions`, `Record.Facts` (`changes_requested []string`, `checks string`, `review_requests []string`, `author`).
- Produces:
  - `type RowKind string`: `RowChangesRequested "changes_requested"`, `RowComments "comments"`, `RowReviewRequested "review_requested"`, `RowChecksFailed "checks_failed"`, `RowOutOfPolicy "out_of_policy"`, `RowReady "ready"`, `RowCannotCheck "cannot_check"`, `RowInfo "info"`. Action kinds equal the prompt kinds in Task 1.
  - `type InboxWork struct { Listing Listing; Assessment *Assessment; Next NextActions; PRs []Record; Mine bool; Err string }` (Mine false for someone else's ticket reached by a review request: no policy rows. Err set when this item could not be read.)
  - `type InboxInput struct { Work []InboxWork; Loose []Record; Activity []Activity; Who map[string]string; Now time.Time }` (`Loose`: PRs with no ticket.)
  - `type InboxRow struct { ID, Fingerprint string; Kind RowKind; Ticket, PR, PRURL, Title, Text, Stage, To, Fix string; Since time.Time; Events []Activity; New int }` with `func (r InboxRow) Action() bool` (`Kind != RowInfo`).
  - `func BuildInbox(in InboxInput, st InboxState) []InboxRow`

  Rules (each a test):
  - Row `ID` is the ticket key, or the PR ID for loose PRs. One row per ID, choosing the most important current kind in this order: out_of_policy, changes_requested, checks_failed, review_requested, comments, ready, cannot_check, info. Other events stay in `Events`.
  - Action kinds come from current state: `changes_requested` from facts (not by me), `checks_failed` when `checks == "failure"` on my PR, `review_requested` when my identity for that connection is in `review_requests`, `out_of_policy`/`ready` from `Next.State` and assessment only when `Mine`, `cannot_check` from `Err`. `comments`: unseen `ActivityComment`/`ActivityReview` events by others on PRs whose `author` is me.
  - Info rows: unseen events not covered above, plus a synthetic "Checks passed" when `st.Checks[pr]` was not `success` and now is.
  - Events whose `WhoID` equals `Who[event.Connection]` are dropped.
  - Fingerprint: kind plus head commit (reviews, checks), sorted requested reviewers (review request), `Next.Summary` (policy), newest event key (comments, info).
  - Hidden when `st.Done[ID] == Fingerprint`, or snoozed with matching fingerprint and `Until` after `Now`. A new event on the ticket changes the fingerprint so it returns.
  - `Since`: newest relevant event `At`; else `st.FirstSeen[ID]`; else `Now` (caller records FirstSeen).
  - `Text` copy: `Bob requested changes on #84`, `Bob left 2 comments on #84`, `Alice asked you to review #97`, `Checks failing on #93`, `Out of policy: <Next.Summary>`, `Ready to move → release`, `Couldn't check: <Err>`, info: `Charlie approved #91`, `Checks passed on #93`, `Alice commented on ABC-10`, `Bob pushed 3 commits to #84`. Repeats fold (`2 comments`, `3 commits`).
  - Order: action rows by `Since` ascending, then info rows by `Since` descending.
